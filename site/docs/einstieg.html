Einstieg & Fleet-Server-Betrieb

Der Fleet-Dienst (fleet/) läuft als ein Docker-Image, das Sie selbst hosten – in der EU, wegen der Datenschutzüberlegung aus Abschnitt 6 der Spezifikation. Dieser Abschnitt beschreibt den Betrieb des Dienstes selbst, nicht einer einzelnen Wohnung – das folgt unter Wohnung hinzufügen.

Mit Docker starten

Das Repository liefert zwei getrennte Images aus einem Repository – eines für die Cloud, eines für den Agenten. Für den Fleet-Server:

docker build -f docker/Dockerfile.fleet -t thermoctl-fleet .
docker run -d --name fleet \
  --env-file .env \
  -p 127.0.0.1:8100:8000 \
  thermoctl-fleet

docker/compose.example.yml zeigt das Zusammenspiel beider Images – ausdrücklich nur zur Veranschaulichung der Topologie, nicht als Rollout-Rezept für mehrere Wohnungen: der Agent läuft tatsächlich auf der Basisstation jeder Wohnung, nicht neben dem Fleet-Dienst.

Kein Secret steht in compose.example.yml oder im Repository. Eigene Werte gehören ausschließlich in eine lokale .env-Datei, die nie committet wird.

Umgebungsvariablen

Alle Werte unten sind direkt aus dem Quellcode abgeleitet (fleet/) – keine davon hat einen Vorgabewert, wo ein Vorgabewert selbst wie eine echte Konfiguration aussähe (CLAUDE.md: „nichts hartcodiert außer den Sicherheitsgrundsätzen“).

TLS und Fingerprint-Pinning

TLS ist nie abschaltbar – auch nicht für Tests (Abschnitt 4 der Spezifikation). Üblicherweise terminiert ein Reverse-Proxy (z. B. Caddy oder nginx) das Zertifikat vor dem Fleet-Container. Zusätzlich zur gewöhnlichen Zertifikatsprüfung kennt jeder Agent den erwarteten SHA-256-Fingerabdruck des Server-Zertifikats (FLEET_CERT_FINGERPRINT, Format sha256:<64 Hex-Zeichen>) – ein zweiter Riegel, falls eine Zertifizierungsstelle kompromittiert würde.

Den Fingerabdruck des eigenen Zertifikats ermitteln:

openssl x509 -in server.crt -noout -fingerprint -sha256

Das Ergebnis (ohne die Doppelpunkte, in Kleinbuchstaben, mit dem Präfix sha256:) ist der Wert für FLEET_CERT_FINGERPRINT.
